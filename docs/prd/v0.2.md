| Field | Value |

> Versi ini menggantikan `docs/PRDv0.1.md` (status Review) sebagai PRD aktif. v0.1 tetap disimpan sebagai arsip. Perubahan utama v0.2: implementasi resmi RDP-UI v1.0 via Django-Cotton + HTMX, halaman default lengkap (auth, public, dashboard), component library (termasuk komponen yang belum ada di RDP-UI v1.0), HTMX pattern sebagai SOP, dan CLI interaktif `rdp new` untuk bootstrap project baru.

---

## 1. Background & Problem

KK mengelola 10+ produk SaaS sebagai solo founder. Masalah dari v0.1 masih berlaku — setiap project baru dimulai dari nol, tanpa standar baku, dengan bug yang sama berulang antar project — dan sejak v0.1 ditulis, muncul konteks baru yang memperjelas masalahnya:

**RDP-UI v1.0 sudah selesai dan live di `cdn.radian.web.id`** (landing page, Examples, Docs), tetapi belum ada jalur implementasi resmi ke Django. Akibatnya:

- Setiap project Django mengulang langkah yang sama: menyusun `base.html` yang me-load PicoCSS → rdp.css → HTMX → rdp.js dalam urutan benar, membuat layout blank/landing/dashboard, menulis ulang halaman login/register/forgot-password, dan membangun ulang dialog box, toast, dan komponen umum lainnya.
- Contoh layout di RDP-UI (Blank, Homepage, Dashboard) berbentuk HTML statis — setiap kali dipakai di Django harus dikonversi manual ke template + komponen Cotton, dan hasil konversinya berbeda-beda antar project.
- RDP-UI v1.0 baru mencakup primitif (button, badge, alert, avatar, card, form, breadcrumb, dropdown, modal, AI loader). Komponen yang dibutuhkan halaman aplikasi nyata — table, pagination, tabs, toast, tooltip, accordion, skeleton, empty state — belum ada, sehingga tiap project mengarangnya sendiri dengan gaya yang tidak seragam.
- Halaman statis yang wajib ada di hampir semua produk (landing, about, terms, privacy) ditulis ulang berkali-kali padahal isinya 90% sama.
- Pattern HTMX (modal form, inline edit, live validation, delete confirmation, dst.) diimplementasikan berbeda di tiap project karena tidak pernah dibakukan sebagai SOP.

Referensi eksternal (dokumen perencanaan, `Plan - ChatGPT.md`) menegaskan hal yang sama: project ini bukan sekadar "template Django + CSS", melainkan **fondasi Product Layer RDP** — semua produk (Taliti, TMPT, KUNCI, SEMOP, dst.) akan dibangun di atasnya. Karena itu scope v0.2 diperluas dari fondasi teknis (v0.1) menjadi fondasi aplikasi utuh: bukan halaman kosong, tetapi aplikasi yang langsung bisa dipakai.

## 2. Goals

- Project baru siap `runserver` dalam **< 5 menit** via CLI interaktif `rdp new` — lengkap dengan halaman auth, public pages, dan dashboard yang sudah jadi (bukan halaman kosong).
- **100% halaman bawaan** dirender melalui komponen django-cotton (`<c-rdp.*>` / `<c-layout.*>`) — tidak ada HTML mentah berulang di template halaman.
- **100% styling halaman bawaan** menggunakan token RDP-UI (`var(--rdp-*)` + class `rdp-*`) — tidak ada warna/spacing hardcoded, tidak ada inline CSS/JS.
- Semua interaksi AJAX menggunakan HTMX dengan pattern yang dibakukan sebagai SOP — developer (dan AI assistant) tinggal mengikuti pattern, bukan mengarang.
- Komponen yang belum ada di RDP-UI v1.0 tersedia di starter kit sebagai komponen Cotton + CSS lokal, dengan jalur upstream ke RDP-UI v1.1.
- Visi jangka panjang 9 layer (Bootstrap → Documentation) terdefinisi sebagai arsitektur produk, dengan pembagian jelas mana yang masuk v0.2 dan mana roadmap v0.3+.

## Non-Goals

- **Bukan rebrand**: nama produk tetap **RDP Starter Kit** (bukan "RDP Django Starter Kit" / "RAS").
- **Auth lanjutan tidak masuk v0.2**: OTP, MFA, lock screen, invitation flow, session management lanjutan → roadmap v0.3+.
- **Dashboard pages lanjutan tidak masuk v0.2**: billing, subscription, API keys, webhook, organization/workspace switcher, audit log UI → v0.3+ (ditambahkan per project sesuai kebutuhan).
- **Komponen berat tidak masuk v0.2**: AI component suite (chat, streaming markdown, prompt box), kanban, calendar, tree view, chart wrapper, rich text/markdown editor, command palette, mega menu → v0.3+ atau roadmap RDP-UI.
- **Generator DX lanjutan tidak masuk v0.2**: `create_crud`, form generator, API generator, dashboard generator → v0.3+. v0.2 hanya `rdp new` + template app.
- **Bukan pengganti dokumentasi RDP-UI**: dokumentasi komponen CSS tetap di `cdn.radian.web.id/docs`; starter kit hanya mendokumentasikan pemakaiannya di Django/Cotton.
- Tidak mendukung multi-tenant di v0.2.
- Tidak ada distribusi via PyPI/npm untuk starter kit — distribusi via git + CLI.

## 3. Success Metric

- **Setup time**: dari `rdp new myproject` sampai `runserver` menampilkan landing page + bisa login ke dashboard dalam **< 5 menit** (diukur stopwatch, environment bersih dengan `uv` terpasang).
- **Zero manual edit**: project hasil `rdp new` berjalan tanpa mengedit satu file pun selain jawaban wizard (SECRET_KEY, nama project, app color di-generate otomatis).
- **Test & CI**: `uv run pytest` 100% pass segera setelah generate; GitHub Actions hijau sejak commit pertama.
- **Konsistensi UI (terukur via CI/lint)**: 0 inline `style=`/`<script>` di template halaman bawaan; 0 warna hex hardcoded di CSS project (semua `var(--rdp-*)`); dicek otomatis oleh script lint template.
- **Cakupan komponen**: 100% halaman bawaan (auth, public, dashboard, error) tersusun dari komponen Cotton; daftar komponen terdokumentasi di `docs/modules/ui-components.md`.
- **Accessibility**: skor Lighthouse Accessibility ≥ 90 untuk semua halaman bawaan, light dan dark mode, sebelum rilis v0.2.
- **Adoption**: minimal 3 project RDP aktif berjalan di atas starter kit v0.2 dalam 60 hari setelah rilis (carry-over dari v0.1).
- **Upstream**: minimal 5 komponen gap (dari: table, pagination, tabs, toast, tooltip, accordion, skeleton, empty state) diusulkan ke RDP-UI v1.1 dalam 90 hari setelah v0.2 rilis.

## 5. Scope

Scope disusun mengikuti arsitektur **9 layer** (diadopsi dari dokumen perencanaan). Semua layer terdefinisi di v0.2; kedalaman implementasinya bertahap.

### In Scope

**Layer 1 — Project Bootstrap**
- CLI interaktif `rdp new <project>`: wizard yang menanyakan nama project, deskripsi, app color (sesuai RDP Color Coding: teal/coral/purple/amber/gold/navy), halaman public opsional (contact, FAQ), lalu menghasilkan project siap `runserver`.
- Generate otomatis: SECRET_KEY, `.env` dari `.env.example`, rename modul, set `--rdp-app-accent`.
- Template app untuk `startapp` (struktur package: `models/`, `views/`, `services/`, `forms/`, `admin/`).

**Layer 2 — UI Foundation**
- `base.html` me-load urutan wajib: PicoCSS → `rdp.css` → HTMX → `rdp.js`, plus CSRF setup untuk HTMX.
- Design token RDP-UI sebagai satu-satunya sumber styling; dark mode via `data-theme`.
- Fallback self-host: salinan lokal `rdp.css`/`rdp.js`/font di `static/` yang bisa diaktifkan via env var jika CDN tidak tersedia.

**Layer 3 — Layout System** (semua sebagai komponen Cotton yang bisa di-override per project)
- `<c-layout.base>` — root layout.
- `<c-layout.public>` — halaman marketing/statis (navbar publik + footer).
- `<c-layout.auth>` — blank layout terpusat untuk login/register/dst. (mengacu contoh "Blank Layout" RDP-UI).
- `<c-layout.dashboard>` — app shell dua kolom (mengacu contoh "Dashboard Layout" RDP-UI).
- `<c-layout.error>` — halaman error/maintenance.
- `<c-layout.email>` — base template email transaksional HTML.
- `<c-layout.print>` — layout ramah cetak.

**Layer 4 — Application Shell**
- Navbar publik, sidebar (collapsible, mobile drawer), topbar (judul halaman + actions), footer, breadcrumb, user menu (avatar + dropdown), theme switcher (light/dark/system), container toast global, container modal global (`<dialog>` native).

**Layer 5 — Authentication & Account**
- Halaman jadi: login, register, logout, forgot password, reset password, verify email, change password, profile (+ avatar).
- Semua form pakai komponen Cotton + validasi HTMX (error = HTTP 422, redirect sukses = `HX-Redirect`).
- Email transaksional (verifikasi, reset password) memakai `<c-layout.email>`.

**Layer 6 — Reusable Components (Component Library)**
- *Sudah ada di RDP-UI v1.0 → dibungkus jadi Cotton*: button, badge, alert, avatar, card, AI loader, form group (input/select/textarea/checkbox/radio), breadcrumb, dropdown, modal/dialog box.
- *Gap — belum ada di RDP-UI v1.0 → dibuat di starter kit (Cotton + CSS lokal), lalu di-upstream ke RDP-UI v1.1*: table (responsive + sortable header), pagination, tabs, toast, tooltip, accordion, skeleton loader, empty state, stat/metric card, confirm dialog, progress bar, drawer, search box, filter bar, file upload, steps/wizard indicator.

**HTMX Patterns (lintas layer — dibakukan sebagai SOP + contoh hidup)**
- CRUD list + form, modal form, delete confirmation, live validation, inline edit, search dengan debounce, pagination fragment, infinite scroll, polling, toast dari server (`HX-Trigger`).
- Setiap pattern punya: contoh kode di project, resep di cookbook, dan konvensi respons (fragment, 422, `HX-Redirect`).

**Layer 7 — Developer Experience (v0.2: dasar saja)**
- `rdp new` (lihat Layer 1) + `manage.py startapp --template`.
- Demo data / sample user via fixture atau management command (agar dashboard tidak kosong saat pertama dibuka).
- Script lint template: deteksi inline CSS/JS dan warna hardcoded (dipakai di CI).

**Layer 8 — Operations (carry-over v0.1, tetap berlaku)**
- Konfigurasi `.env`, Custom User model, security headers, logging terstruktur, cache, email backend, static/media (WhiteNoise + S3-ready), error pages (403/404/500) + halaman maintenance, CI GitHub Actions (lint → test → migration check).

**Layer 9 — Documentation & SOP**
- `docs/` terstruktur: `prd/`, `prd/user-stories/`, `architecture/`, `decisions/` (ADR), `modules/`, `cookbook/`, `sop/`.
- SOP: Frontend structure (sudah ada — `SOP-FRONTEND-STRUCTURE.md`, dipindah ke `docs/sop/`), HTMX pattern, Cotton component (naming, props, slot), Git (branch/commit/release), Testing, Dokumentasi.
- Cookbook per resep: "buat CRUD", "buat modal HTMX", "buat wizard", "tambah app baru", "aktifkan Celery/ASGI/DRF".
- Skills AI di `.claude/` menjadi bagian resmi repo (spesifikasi, bukan sekadar panduan): rdp-ui, django, htmx, django-cotton, dst.

**Halaman default yang disertakan v0.2**
- Public: landing page (hero, fitur, CTA, footer — mengacu "Homepage Layout" RDP-UI), about, terms, privacy; contact + FAQ opsional via wizard CLI.
- Auth: login, register, forgot/reset password, verify email, change password, profile.
- App: dashboard (KPI cards + tabel + chart placeholder), settings, notifications (list sederhana).
- Sistem: 403, 404, 500, maintenance.

### Out of Scope (roadmap v0.3+ / RDP-UI)

- OTP, MFA, lock screen, invitation, session management UI.
- Billing, subscription, API keys, webhook, organization/role/permission management UI, audit log UI.
- AI components (chat, prompt box, streaming markdown, citation, model picker), kanban, calendar, tree view, JSON/code/log viewer, chart wrapper, rich text/markdown editor.
- Command palette, mega menu, context menu, workspace/organization switcher.
- Generator lanjutan: `create_crud`, form/API/dashboard/component generator, migration helper.
- Public pages lanjutan: pricing, blog, docs site, status page, coming soon.
- Multi-tenant, REST API (DRF), GraphQL, WebSocket, Celery, Docker — tetap instruksi di docs (carry-over v0.1).

## 6. Functional Requirements

> FR dikelompokkan per layer. FR bertanda **(c/o v0.1)** adalah carry-over dari PRD v0.1 yang tetap berlaku; detail acceptance criteria dipecah ke User Story (skill 02).

**Bootstrap & CLI**

**FR-01** — CLI `rdp new <project>` berjalan interaktif: menanyakan nama project, deskripsi singkat, app color (pilihan RDP Color Coding), dan halaman opsional (contact, FAQ). Hasilnya project lengkap yang lolos `uv sync && migrate && runserver` tanpa edit manual.

**FR-02** — CLI men-generate SECRET_KEY unik, menyalin `.env.example` → `.env` dengan nilai development aman, me-rename semua referensi nama project, dan men-set `--rdp-app-accent` sesuai pilihan warna.

**FR-03** — Tersedia template app custom untuk `manage.py startapp --template` dengan struktur package (`models/`, `views/`, `services/`, `forms/`, `admin/`, `urls.py`) sesuai konvensi CLAUDE.md.

**FR-04 (c/o v0.1)** — Alternatif tanpa CLI tetap didukung: clone repo + salin `.env.example` → `runserver` jalan (jalur lama v0.1 tidak boleh rusak).

**UI Foundation & Layout**

**FR-05** — `base.html` me-load aset dalam urutan wajib PicoCSS → rdp.css → HTMX → rdp.js, menyertakan meta CSRF + listener `htmx:configRequest` (di file JS terpisah, bukan inline), skip-nav link, dan atribut `data-theme`.

**FR-06** — Mode self-host: dengan satu env var (mis. `RDP_UI_SELF_HOST=True`), semua aset RDP-UI/PicoCSS/HTMX dilayani dari `static/` lokal tanpa perubahan template.

**FR-07** — Tujuh layout tersedia sebagai komponen Cotton (`<c-layout.base|public|auth|dashboard|error|email|print>`), masing-masing bisa di-override per project dengan membuat file yang sama di `templates/cotton/layout/`.

**FR-08** — App shell dashboard: sidebar collapsible (drawer di mobile), topbar dengan slot actions, breadcrumb, user menu, theme switcher yang menyimpan preferensi, toast container, dan modal container global. Mobile-first: semua berfungsi di viewport 375px.

**Authentication & Account**

**FR-09 (c/o v0.1, diperluas)** — Alur auth lengkap (login, register, logout, forgot password, reset password, verify email, change password, profile + avatar) berfungsi out-of-the-box, semua halaman memakai `<c-layout.auth>` dan komponen form Cotton.

**FR-10** — Validasi form real-time via HTMX: error field dikembalikan sebagai fragment dengan HTTP 422; sukses submit full-page memakai `HX-Redirect`. Konvensi ini berlaku seragam di semua form bawaan.

**FR-11** — Email transaksional (verifikasi, reset password) memakai `<c-layout.email>` dengan styling inline-safe yang konsisten dengan brand RDP.

**Public & App Pages**

**FR-12** — Halaman public siap pakai: landing (hero, grid fitur, CTA, footer), about, terms, privacy — kontennya placeholder terstruktur yang tinggal diganti per project; contact + FAQ di-generate hanya jika dipilih di wizard.

**FR-13** — Dashboard default berisi KPI/stat cards, tabel data (dengan pagination), dan area chart placeholder — terisi demo data dari fixture sehingga tidak pernah tampil kosong saat pertama kali dibuka.

**FR-14 (c/o v0.1)** — Error pages 403/404/500 + halaman maintenance memakai `<c-layout.error>`, terdaftar di `config/urls.py`.

**Component Library**

**FR-15** — Semua komponen RDP-UI v1.0 terbungkus sebagai komponen Cotton bernamespace `<c-rdp.*>` (button, badge, alert, avatar, card, loader, form group, breadcrumb, dropdown, modal) dengan props terdokumentasi (variant, size, state) dan default yang aksesibel (aria-label, focus-visible).

**FR-16** — Komponen gap dibuat di starter kit sebagai Cotton + CSS lokal (`static/css/components/*.css`): table, pagination, tabs, toast, tooltip, accordion, skeleton, empty state, stat card, confirm dialog, progress, drawer, search box, filter bar, file upload, steps/wizard. CSS-nya ditulis dengan konvensi dan token RDP-UI agar siap di-upstream ke v1.1 tanpa perombakan.

**FR-17** — Dialog box: satu komponen `<c-rdp.modal>` berbasis `<dialog>` native dengan varian ukuran, plus `<c-rdp.confirm>` untuk konfirmasi destruktif (judul, pesan, tombol batal/lanjut, terintegrasi pattern HTMX delete).

**FR-18** — Setiap komponen punya halaman demo internal (`/dev/components/`, hanya DEBUG) yang menampilkan semua varian — berfungsi sebagai dokumentasi visual dan smoke test.

**HTMX Patterns**

**FR-19** — Minimal 10 pattern HTMX terimplementasi sebagai contoh hidup di project + resep cookbook: CRUD, modal form, delete confirmation, live validation, inline edit, search debounce, pagination fragment, infinite scroll, polling, toast via `HX-Trigger`.

**Developer Experience & Quality**

**FR-20** — Management command demo data: membuat sample user (admin + user biasa) dan data contoh untuk dashboard dalam satu perintah.

**FR-21** — Script lint template berjalan di CI: gagal jika ada inline `style=`, blok `<script>` inline (di luar whitelist), atau warna hex hardcoded di template/CSS project.

**FR-22 (c/o v0.1)** — Fondasi operasional v0.1 tetap: `.env` terpusat, Custom User model, security headers, logging terstruktur, cache via env, email via env, WhiteNoise + S3-ready, admin dikustomisasi, `uv run pytest` 100% pass, CI lint → test → migration check.

**Documentation & SOP**

**FR-23** — Struktur `docs/` dirapikan: `prd/` (PRD versi aktif + arsip), `prd/user-stories/`, `architecture/`, `decisions/`, `modules/`, `cookbook/`, `sop/`. File existing (PRDv0.1.md, user-stories, SOP-FRONTEND-STRUCTURE.md) dipindah ke lokasi barunya.

**FR-24** — SOP tersedia dan dirujuk dari CLAUDE.md: frontend structure, HTMX pattern, Cotton component (naming/props/slot), Git workflow, testing, dokumentasi modul.

**FR-25** — Cookbook berisi resep langkah-demi-langkah minimal: buat CRUD baru, buat modal HTMX, buat wizard multi-step, tambah app baru, ganti app color, aktifkan fitur opsional (Celery, ASGI, DRF, S3).

**FR-26** — Skills AI (`.claude/`) diperlakukan sebagai spesifikasi resmi: setiap perubahan konvensi di starter kit wajib diikuti update skill terkait (rdp-ui, django-cotton, htmx) dalam commit yang sama.

## 7. Non-Functional Requirements

**Performa:** `runserver` boot < 5 detik; `uv sync` < 2 menit; halaman bawaan tanpa bundler/build step — CSS/JS murni via CDN atau static.

**Keamanan (c/o v0.1):** default production-safe — `DEBUG=False` di production, `ALLOWED_HOSTS` via env, CSRF aktif (termasuk semua request HTMX), secure cookie, CSP, HSTS. Halaman `/dev/components/` tidak pernah ter-expose di production.

**Accessibility:** WCAG 2.2 AA untuk semua halaman & komponen bawaan — label form terasosiasi, `aria-label` tombol ikon, `aria-live` pada container HTMX, `aria-busy` saat loading, focus-visible tidak di-disable, navigasi keyboard penuh pada modal/dropdown/tabs.

**Responsif:** mobile-first; semua halaman bawaan diuji di 375px dan 1280px; sidebar menjadi drawer di mobile; tabel punya mode responsive (scroll/stack).

**Dark mode:** semua halaman & komponen bawaan tidak pecah di `data-theme="dark"`; tidak ada override manual variabel warna di luar mekanisme RDP-UI.

**Konsistensi & Maintainability:** 0 inline CSS/JS di template (di-enforce CI); styling hanya via class `rdp-*`, token `--rdp-*`, atau CSS file per fitur; komponen Cotton adalah satu-satunya cara memakai markup UI berulang.

**AI Friendliness (c/o v0.1):** naming deskriptif, struktur flat, konvensi terdokumentasi di CLAUDE.md + skills; setiap komponen/pattern punya contoh yang bisa ditiru langsung.

**Coverage (c/o v0.1):** ≥ 80% untuk kode di `apps/`.

**Dependency (c/o v0.1):** minimal, versi eksplisit di `pyproject.toml` (bukan `*`), install hanya via `uv add`.

## 9. Risks

| Risk | Dampak | Mitigasi |
|---|---|---|
| Scope creep dari visi 9 layer — semua ingin masuk v0.2 | v0.2 tidak pernah rilis | Non-Goals eksplisit per layer; fitur baru hanya boleh masuk lewat revisi PRD, bukan "sekalian" |
| Dobel maintenance komponen gap (starter kit vs RDP-UI v1.1) | Dua versi komponen drift, styling tidak seragam | CSS komponen gap ditulis dengan konvensi RDP-UI sejak awal; setelah upstream diterima, starter kit beralih ke versi CDN dan menghapus lokal |
| CLI interaktif memakan waktu development besar | Bootstrap jadi bottleneck rilis | MVP wizard maksimal 5 pertanyaan; sisanya default. Jalur clone manual (FR-04) tetap jadi fallback |
| RDP-UI CDN down / URL berubah | UI rusak di semua project | Pin versi di template + mode self-host via env var (FR-06) |
| Konvensi ganda: class `rdp-*` (CSS) vs `<c-rdp.*>` (Cotton) membingungkan | Developer/AI memakai markup mentah, komponen tidak dipakai | Halaman demo komponen (FR-18) + skill AI yang selalu update (FR-26) + lint template (FR-21) |
| rdp.js vs Alpine.js vs HTMX tumpang tindih menangani interaksi | Perilaku ganda/bentrok (mis. dropdown ditangani dua library) | SOP menetapkan pembagian: HTMX = server round-trip, rdp.js = perilaku komponen RDP, Alpine = state lokal sisa; didokumentasikan per komponen |
| Starter kit drift dari project aktif (c/o v0.1) | Standar tidak diikuti | Dipakai di minimal 1 project nyata dalam 30 hari setelah rilis |
| Halaman bawaan terlalu "opinionated" untuk produk tertentu | Developer membongkar banyak template | Semua layout/komponen bisa di-override per project (FR-07); konten halaman public berupa placeholder terstruktur |

## 10. Open Questions

1. **Bentuk distribusi CLI `rdp new`**: standalone tool via `uv tool install` dari git repo, atau script `rdp-new.py` di dalam repo starter kit yang dijalankan `uv run`? Berpengaruh ke cara update CLI antar versi.
2. **Repo komponen upstream**: apakah upstream ke RDP-UI v1.1 lewat repo `radianapp/rdpui` langsung (PR), dan siapa yang menentukan komponen "lulus" ke CDN — perlu kriteria stabil (dipakai ≥ 2 project? tidak berubah 30 hari?).
3. **Versi RDP-UI di CDN**: URL aset saat ini tidak berversi (`/assets/rdp.css`). Apakah RDP-UI akan menyediakan path berversi (mis. `/v1/rdp.css`) agar starter kit bisa pin versi dengan aman? Ini kebutuhan dari sisi starter kit ke project RDP-UI.
4. **Notifications app**: halaman notifications v0.2 cukup list statis dari model sederhana, atau perlu real-time (polling HTMX)? Default usulan: model + list + polling ringan, tanpa WebSocket.
5. **Konten legal (terms, privacy)**: disediakan sebagai template placeholder saja, atau perlu draft konten standar RDP yang di-review legal? Placeholder dulu — perlu konfirmasi.
