Why RDP UI

vs. writing custom CSS
A design system takes months to get right — tokens, dark mode, focus states, contrast. RDP UI is that system, already audited, already themed, maintained for you.
vs. Bootstrap
No 2014 look, no jQuery-era patterns, no fighting the theme. RDP UI is variable-driven, soft and modern — and its components are Django templates, not copy-paste markup.
vs. React component libraries
shadcn and Chakra are excellent — for React. RDP UI gives Django the same caliber of components without a JS build, a second router, or an API layer you didn't need.

Three ways in, one component

Start with plain HTML, graduate to Cotton, add HTMX when you need it.

1 · Plain HTML
<article class="rdp-card">
  <header>API usage</header>
  <p>71% of quota used.</p>
  <footer>
    <button>Upgrade</button>
  </footer>
</article>
2 · Django Cotton
<c-rdp.card>
  <c-slot name="header">API usage</c-slot>
  71% of quota used.
  <c-slot name="footer">
    <c-rdp.button variant="primary">Upgrade</c-rdp.button>
  </c-slot>
</c-rdp.card>
3 · + HTMX
<c-rdp.card hx-get="/usage"
    hx-trigger="every 30s">
  <c-slot name="header">API usage</c-slot>
  <c-rdp.skeleton lines="2" />
</c-rdp.card>
<!-- server renders the fragment -->
