Interaction & motion guidelines

Interaction rules
I1
Feedback timing. <100ms: no indicator. 100ms–1s: inline spinner. >1s: skeleton or progress. >10s: move to background + notify on completion.
I2
Server-confirmed by default. UI changes when the server says so. Optimistic updates only for reversible, private, high-frequency actions (toggling a star) — never for money, deletion, or shared state.
I3
Disabled while pending. The triggering control disables during flight (hx-disabled-elt="this"); the rest of the page stays interactive. Double-submits are impossible by construction.
I4
Error recovery. Every failure leaves a retry path in place: the form keeps its values, the toast offers retry, the region shows an error state with a button. Reloading the page is never the recovery mechanism.
I5
URL is state. Anything worth bookmarking (filters, page, open record) lives in the URL via hx-push-url. Back always works.

M1
Only opacity and transform animate. Fades, small translates (≤8px), scale 0.98→1. Never width/height/top/left, never color cycling, never layout-shifting motion.
M2
Never animates: text while reading, tables during sort/filter (instant swap), focus movement, anything on initial page load. Motion explains change; it doesn't decorate.
M3
prefers-reduced-motion: all durations drop to 1ms globally — states still change, nothing travels. Spinners become static progress text updated via aria-live.
