Anatomy of an RDP component

Every component is the same four layers. Learn one, know them all — that's the Minimal API principle mechanized.

1 · Wrapper
One semantic root element (button, dialog, nav…) with class rdp-{name}. Extra attributes pass through — hx-*, id, data-* land on the root.
2 · Slots
Default slot = the tag's children. Named slots (header, footer, icon…) are optional; an empty slot renders nothing — no ghost padding.
3 · States
Native where possible (:hover, :disabled, aria-invalid, aria-current); style hooks target those, never state classes like .is-active.
4 · Tokens
All visuals via --rdp-{name}-* component tokens defaulting to semantic tokens. Zero literals inside a component's CSS.

Composition model
C1Components nest freely. Any component can appear in any slot — a button in a card footer, a badge in a table cell, a form in a modal.
C2Slots over props. If content could ever be more than a string, it's a slot, not a prop. Props configure; slots compose.
C3Convenience props are shorthand. title="…" exists for the 80% case and is exactly equivalent to filling the slot.
C4No hidden layout. Components size to their container; parents own spacing via stack/grid — a component never sets its own margins.
C5HTMX rides along. Interactivity is attributes on the same tags — components are transport-agnostic and work with plain form posts too.
