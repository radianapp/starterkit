RDP UI · Product Foundation
v0.1 · July 2026

The UI framework Django never shipped.

A complete, server-first UI ecosystem — design system, CSS framework, Cotton components, HTMX patterns, themes, and templates — built natively for Django. Modern UI Framework for Django.

01

Product positioning

For Django teams who want a polished product without adopting a frontend stack, RDP UI is the UI framework that turns semantic HTML into a finished interface — components, themes, and interaction patterns that speak Django natively.

Unlike CSS toolkits that stop at styling, or component libraries that assume React, RDP UI covers the whole surface of a real product — from a button to a billing page — inside the templates Django developers already write.

Framework What it is Why it falls short for Django teams
Tailwind UI Paid component gallery on utility-class CSS Utility-class soup in templates; React/Alpine-leaning; no Django integration
shadcn/ui Copy-paste React components Requires the React + build-tool stack Django teams are avoiding
PicoCSS Elegant classless CSS for semantic HTML Stops at primitives — no components, patterns, or product templates
Bootstrap The long-standing default CSS framework Instantly recognizable, dated look; no server-first interaction story
Chakra UI Accessible, themeable React system React-only; unusable from a Django template
DaisyUI Themed component classes on Tailwind Still utility CSS underneath; themes without a backend or component model
RDP UI Complete UI ecosystem for Django Design system → CSS → Cotton components → HTMX patterns → themes → templates, one coherent stack
The wedge

The only complete UI ecosystem natively built for Django + Cotton + HTMX. Every component is one tag away — <c-rdp.button> — with server-first interactivity and zero build step.

02

User personas

Persona 1 · Indie
The solo Django developer
Goals

Ship side projects and client work fast, alone, without babysitting a frontend toolchain.

Pains

The UI takes longer than the backend; every project restarts from a blank stylesheet.

RDP UI gives them

A full component catalog and ready themes — drop <c-rdp.*> tags into templates and the product looks finished on day one.

Persona 2 · Backend
The backend engineer with no design skills
Goals

Build internal tools that don't look homemade — without learning design.

Pains

Can't judge spacing, type, or color; copy-pasted CSS breaks and accessibility is a mystery.

RDP UI gives them

Correct-by-default components: design decisions pre-made, WCAG AA, keyboard navigation, and focus states baked in.

Persona 3 · Startup
The founder shipping a SaaS
Goals

Look credible to customers and investors now; iterate on product weekly.

Pains

No budget for frontend hires; a React SPA doubles the stack and halves the pace.

RDP UI gives them

SaaS-shaped templates — auth, dashboard, settings, billing — plus theming for their brand and HTMX interactivity without SPA cost.

Persona 4 · Enterprise
The team lead standardizing internal tools
Goals

One consistent, compliant UI standard across dozens of Django tools and teams.

Pains

Every tool looks different; accessibility audits fail; onboarding new hires to N ad-hoc UIs is slow.

RDP UI gives them

A single versioned design system: shared tokens, documented components, audit-ready accessibility — governance without a design department.
